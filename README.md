# Foundational Models for Meme Understanding

This repository contains the code, experiments, and evaluation tools for the **Foundational Models for Meme Understanding** project.

The goal of the project is to evaluate modern foundation models and Vision-Language Models (VLMs) on multimodal meme-understanding tasks.

The project focuses on problems such as:

- Meme understanding
- Hate speech detection
- Humor and sarcasm detection
- Sentiment analysis
- Multimodal reasoning
- Image-text interaction
- Explanation generation
- Hallucination analysis
- Model error analysis
- Cross-dataset evaluation

Models and libraries used in the project may include Hugging Face Transformers, PyTorch, LLaVA, Qwen-VL, CLIP, ViT, and other multimodal foundation models.

### Folder descriptions

- `data/`: datasets used in the experiments.
- `data/raw/`: original datasets.
- `data/processed/`: preprocessed datasets.
- `notebooks/`: Jupyter notebooks used for exploration and experiments.
- `src/datasets/`: dataset loading and preprocessing code.
- `src/models/`: model loading, inference, and training code.
- `src/evaluation/`: evaluation metrics and benchmarking code.
- `src/utils/`: shared utility functions.
- `outputs/figures/`: generated figures and plots.
- `outputs/predictions/`: model predictions.
- `outputs/tables/`: experiment result tables.

Large datasets, model checkpoints, virtual environments, and generated experiment outputs should generally not be committed to Git.

# 2. Requirements

Before setting up the project, install:

- Git
- Python 3.12 or newer
- Visual Studio Code (recommended)
- An NVIDIA GPU is recommended for running Vision-Language Models

The project uses a Python virtual environment to isolate its dependencies.

# 3. Clone the Repository

Clone the repository:

```bash
git clone https://github.com/HadiFouani/meme-understanding.git
```

Then enter the project directory:

```bash
cd meme-understanding
```

---

# 4. Create the Python Virtual Environment

The virtual environment only needs to be created once.

## Windows

Create the environment:

```bash
py -m venv .venv
```

If several Python versions are installed, a specific version can be used:

```bash
py -3.13 -m venv .venv
```

The project virtual environment will be created inside:

```text
.venv/
```

This folder must not be committed to Git.

---

# 5. Activate the Virtual Environment

The environment should be activated every time a new terminal is opened before running the project.

## Windows Command Prompt

```cmd
.venv\Scripts\activate
```

## Windows PowerShell

```powershell
.venv\Scripts\Activate.ps1
```

## Git Bash

```bash
source .venv/Scripts/activate
```

After activation, the terminal should begin with:

```text
(.venv)
```

For example:

```text
(.venv) C:\Users\user\Desktop\meme-understanding>
```

To deactivate the environment:

```bash
deactivate
```

---

# 6. Install Project Dependencies

Make sure that the virtual environment is activated first.

Upgrade `pip`:

```bash
python -m pip install --upgrade pip
```

Then install the project dependencies:

```bash
python -m pip install -r requirements.txt
```

All packages should be installed inside `.venv` rather than globally on the computer.

# 7. PyTorch and GPU Support

This project uses PyTorch for deep-learning models.

For machines with an NVIDIA GPU, install the appropriate CUDA-enabled version of PyTorch using the installation command generated by the official PyTorch installation selector.

For example, a CUDA-enabled installation can look similar to:

```bash
python -m pip install torch torchvision --index-url <PYTORCH_CUDA_INDEX>
```

The exact CUDA version can depend on the current PyTorch release and the machine configuration.

Do not assume that the CUDA version displayed by `nvidia-smi` must exactly match the CUDA runtime bundled with PyTorch.

---

# 8. Verify PyTorch and GPU

Check whether PyTorch can access the GPU:

```bash
python -c "import torch; print('PyTorch:', torch.__version__); print('CUDA:', torch.cuda.is_available()); print('GPU:', torch.cuda.get_device_name(0) if torch.cuda.is_available() else 'CPU')"
```

A successful GPU configuration should display something similar to:

```text
PyTorch: 2.x.x
CUDA: True
GPU: NVIDIA GeForce ...
```

If:

```text
CUDA: False
```

PyTorch is currently using the CPU.

Tokens, API keys, and credentials must never be committed to Git.

If Git reports that the branch does not have an upstream branch, use:

```bash

```

For another branch:

```bash
git push -u origin <branch-name>
```

After the upstream is configured, future pushes can simply use:

```bash

```

---

# 15. Working with Branches

For larger features or experiments, contributors should preferably create a separate branch rather than working directly on `main`.

Update `main` first:

```bash
git checkout main
git pull
```

Create a new branch:

```bash
git checkout -b feature/model-name
```

For example:

```bash
git checkout -b feature/llava-baseline
```

Work normally and then:

```bash
git add .
git commit -m "Add LLaVA baseline"
git push -u origin feature/llava-baseline
```

A Pull Request can then be opened on GitHub to merge the branch into `main`.

---

# 16. Pull Before Push

Because several contributors may work on the repository, always synchronize before pushing important changes.

Run:

```bash
git pull
```

before beginning new work whenever possible.

If Git reports conflicts, do not overwrite other contributors' work without checking the conflicting files.

# 24. Important Rules for Contributors

Before committing:

1. Run `git status`.
2. Make sure `.venv/` is not being committed.
3. Do not commit datasets unless explicitly required.
4. Do not commit large model weights.
5. Do not commit Hugging Face tokens.
6. Do not commit API keys.
7. Do not commit `.env`.
8. Do not commit generated outputs unnecessarily.
9. Pull the latest repository changes before starting new work.
10. Use descriptive commit messages.

Good commit messages:

```text
Add LLaVA baseline
Add Hateful Memes dataset loader
Implement macro F1 evaluation
Fix image preprocessing
Add hallucination analysis
Update project dependencies
```

Avoid unclear messages such as:

```text
update
changes
fix
test
stuff
```

# 26. Reproducibility

When adding experiments, contributors should record important configuration information such as:

- Model name
- Model version
- Dataset
- Dataset split
- Prompt
- Random seed
- Batch size
- Quantization method
- Evaluation metric
- Hardware
- Relevant hyperparameters

Whenever possible, experiments should be reproducible by another contributor from the repository code and documented configuration.

---

# 27. Security

Never commit secrets to GitHub.

This includes:

```text
Hugging Face tokens
OpenAI API keys
GitHub tokens
Passwords
Private SSH keys
Other API credentials
```

Secrets should be stored using environment variables or local `.env` files.

The `.env` file is ignored by Git and must remain local.
